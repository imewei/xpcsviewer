# xpcsviewer-gui v0.1.11: desktop release scope and design

Date: 2026-11-23. Status: draft for approval.
Evidence: parity audit `three-brain-out/2026-11-23-full-parity-audit/`
(`parity-audit.md`, `probe_*.py`, `probe-results.json`) and the independent
verification of it on the same date. IDs below (M##, V##, W##) are audit IDs.

## Intent

The `xpcsviewer-gui` Python wheel is a desktop tool. v0.1.11 lets a user go
from detector frames to a registered Q-map, then inspect, fit, average and
regroup the resulting XPCS data, and be able to trust what the app reports. The
parity audit says the upstream-adoption branch fails full upstream parity;
v0.1.11 does not chase full parity. It fixes the defects that change which
pixels enter an analysis or how a result is interpreted, fills the gaps along
the existing desktop workflow, and documents every deliberate difference.

## Goals

- Ship Priority 1 (correctness fixes) and Priority 2 (workflow completion)
  together as v0.1.11.
- Every behaviour change has a regression test that fails before the change.
- Every intentional difference from upstream is written down in user docs.

## Non-goals

- Native desktop installers on any OS (M38). The Python wheel stays in scope.
- The historical Dash viewer and the browser UI (W01-W09, M36, M37).
- Priority 3 items: APS 9-ID-D and other detector readers (M07, M09-M13),
  batch Q-map combine and PDF/PNG reports (M31, M32, M35), shared-memory
  averaging (V20). They are deferred until a workflow needs them.
- Full upstream parity. "Different" rows that are deliberate local policy
  (strict denominators, 1-based Q-bin, range clamp, standalone export marker,
  explicit sparse regroup IDs, split Q-map pair rejection) stay as they are.

## Anti-goals

- Do not change numerics that already match upstream (M25, M26, M30, V03,
  V06, V23). Their probes must keep passing.
- Do not add dependencies beyond `scikit-image`.
- Do not call a feature verified against APS data. The two representative APS
  comparisons (V31: raw stack plus unnormalised G2 cube plus registered
  Q-map) have no accessible data; release notes must say they are unverified.

## Constraints

- Base: branch `codex/upstream-adoption` at `e3dab2b` (26 commits ahead of
  `master`; Stages 1-3 live only there). v0.1.11 is released from that line.
- The wheel distribution name is `xpcsviewer-gui`; version comes from
  setuptools-scm.
- Python 3.12+, uv, ruff, mypy strict at API boundaries. Qt tests run with
  `QT_QPA_PLATFORM=offscreen`. Numerical logic stays out of the Qt layer.
- Each stage has its own plan in `docs/superpowers/plans/` and a read-only
  review of its immutable diff, as in Stages 1-3. Parallel lanes use
  separate worktrees.

## Approaches considered and chosen

Build structure (chosen: hybrid). Stage 4 first, then two parallel lanes,
then a merge stage. Rejected: one fully serial line (slow), fully parallel
worktrees (the mask work collides in the SimpleMask kernel).

ROI masks (chosen: port upstream rasteriser). Rejected: patching
`SimpleMaskKernel.apply_drawing` around pyqtgraph's `getArrayRegion`, which
stays tied to pyqtgraph resampling and does not match upstream edge pixels;
and a home-grown polygon fill, which cannot be proven pixel-identical to
upstream. Cost accepted: add `scikit-image` to wheel dependencies.

## Stages

### Stage 4: correctness (first, serial)

1. **ROI masks (M18).** Port upstream `core/rasterize.py` (`RoiPolygon`,
   `circle_vertices`, `ellipse_vertices`, `rectangle_vertices`,
   `line_vertices`, `rasterize`, plus `group_index_map` for Lane A) into
   `xpcsviewer/simplemask/`. Add an adapter that turns each pyqtgraph ROI
   (polygon, circle, ellipse, rectangle, `LineROI`, including rotation) into
   image-space vertices; `apply_drawing` rasterises them instead of pasting
   `getArrayRegion` blocks. Note the coordinate convention: pyqtgraph is
   (x=column, y=row), upstream vertices are (row, column). Reproduced defect:
   on a 24x28 image `LineROI((5,4),(17,14),3)` excludes rows 2-4, columns 4-19
   (an unrotated rectangle at the wrong place); a vertical line becomes a
   horizontal 3x15 bar. Add `scikit-image` to `pyproject.toml` and `uv.lock`
   and confirm a clean wheel install can import it.
2. **Mask import failure (M20).** `SimpleMaskKernel.load_mask` currently logs
   a shape mismatch and still returns `True` (reproduced: 5x7 file onto a
   6x8 detector). It returns `False`, leaves mask and history untouched, and
   the window shows the failure in the status bar. The window's
   `_validate_mask_dimensions` pre-check (modal "Dimension Mismatch" prompt
   that promises cropping or padding, flags valid transposed masks, and
   precedes the kernel call) is removed so the kernel is the single
   validator; the modal "Load Failed" box is replaced by the status message.
3. **Layer replacement (M21).** `MaskAssemble.apply` ANDs the new layer onto
   the current combined mask, so a second draw or parameter edit adds to the
   first (reproduced: two draw layers both stay excluded). Keep per-layer
   arrays; a draw or parameter edit replaces only its own layer and the
   combined mask is recomputed from all layers (threshold, file, manual
   pixels, other). Undo, redo and reset keep working and restore layer state.
4. **Explicit fit parameters (V14a).** `fitting/legacy.py:fit_with_fixed`
   (and `_parallel`, `_sequential`) fix a parameter at its `p0` value, and at
   the bounds midpoint when `p0` is `None`; upstream fixes at the upper bound.
   The fit UI has only min/max bound spin boxes and fit checkboxes (no
   initial-value entry); `XpcsFile.fit_g2` computes `p0` as the bounds
   midpoint (geometric mean for tau). Make the solver API explicit: when any
   parameter is fixed and `p0` is `None` (or non-finite for a fixed entry),
   raise `ValueError`. One shared helper computes the initial guess for
   `fit_g2`. (`fit_g2_high_performance` has no callers and already fails when
   converting its results; it is left alone.) User-facing rule to document: an
   unchecked parameter is held at the midpoint of its min/max bounds
   (geometric mean for tau parameters), unlike upstream's upper bound. A UI
   entry for an explicit fixed value is deferred (see Open items).
5. **Averaging with all inputs rejected (V19).** The job now stays in
   `running`; upstream finishes. It must reach a terminal state, emit its
   status and finished signals, write no output file, and tell the user
   nothing was averaged.
6. **Wheel version (V30).** `xpcsviewer/__init__.py` calls
   `version("xpcsviewer")`; the distribution is `xpcsviewer-gui`, so it falls
   back to a hard-coded `0.1.10`. Look up `xpcsviewer-gui`. The fallback must
   not name a real release. The log banner ("vunknown") and `--version` use
   the same value.
7. **Transmission Q-map: swing angles and `q` magnitude (M16).**
   `compute_transmission_qmap()` has no swing arguments, so upstream's
   swung-geometry call raises `TypeError`. Add `swing_angle_horizontal` and
   `swing_angle_vertical` (default 0) to every code path (the cached NumPy
   backend, the JAX-JIT path and `compute_qmap`, which reads them from
   metadata). Also correct `q`: local computes `q = k0 sin(alpha)` (the
   in-plane projection); upstream's momentum-transfer magnitude is
   `q = 2 k0 sin(alpha/2)`, which differs by about 1.5% at 20 degrees and is
   present even with zero swing. `qx`/`qy` keep `k0 sin(alpha)` times
   `cos/sin(phi)` as upstream does. This changes saved Q-maps for
   wide-angle transmission data and Q partitions derived from `q`; the
   changelog and release notes must say so. Results must agree with
   upstream at the pin (float64 here, upstream stores `qx`/`qy` as float32).

### Lane A: SimpleMask workflow (after Stage 4, serial inside the lane)

Each lane starts with its own short design for the UI-facing details (what a
reopened partition restores and what the editor shows, how the ellipse and
group modes appear). This document fixes scope, not those details.

- TIFF mask import and export alongside HDF5, with provenance (M20).
- Reopen a result file together with its saved partition (M14).
- Outlier masking: circular-ring and adjacent-box methods, percentile and
  MAD thresholds, regional selection (M24); port from upstream
  `outlier_removal.py`.
- Ellipse partition and group-index subpartitions for drawn or parameter
  masks (M27, M28), using `group_index_map` from Stage 4.
- Keep and regression-protect: APS 8-ID-I raw-frame selection and preview
  (M01-M05), mask undo/redo (M22), Q-map export (M30).

### Lane B: Viewer (after Stage 4, parallel to Lane A)

- Detector-space per-pixel G2 inspection (V22). Upstream's view shows a
  detector-space delay slice for raw G2, IP, IF and normalised G2. Scope for
  this release (pending approval): a mode of the existing G2 Map tab (no
  13th tab) showing the normalised G2 of the loaded file at a user-chosen
  delay, with the Q-map/mask overlay available. Raw G2, IP and IF are
  excluded because the viewer does not load the unnormalised cube and no APS
  data is available to verify it.
- Stability-segment averaging accepts both observed HDF5 key names (V21).
  The audit fixture `probe_core_parity.py` cases `segments` and
  `segments_both_keys` show one name currently produces no file.

### Final stage: merge and release

- Merge both lanes; resolve any conflict in the mask layer code.
- User docs: every deliberate difference from upstream, including regroup
  policy (explicit sparse bin IDs, rejection of non-positive denominators,
  standalone export that preserves the source file, split Q-map pair
  rejection), 1-based Q-bin validation, range clamp, fixed-parameter rule.
- Test regroup against representative APS inputs where available; otherwise
  state in release notes that the two APS comparisons are unverified.
- Re-run the audit probes (`probe_core_parity.py` four sides, GUI probes) and
  record which rows moved. Build the wheel, install it in a clean environment,
  check import, `--version`, and launch headless. `make lint`, tests,
  `graphify update .`, changelog, tag v0.1.11.

## UX contracts (my calls)

- Mask import failure and empty averaging report through a non-modal status
  message plus a log entry; no modal dialog on those paths (offscreen tests
  must not block on dialogs).
- The empty-averaging message is shown by the existing 1 Hz job poll (the desktop does not connect the `finished` signal): it stops the timer and writes "Averaging finished: no valid dataset; no output written" to the status bar.
- Clicking Apply with no pending drawings does nothing and says so; it never clears the previous draw layer. ROIs that are degenerate, fall outside the image, or fill no pixel are ignored, including inclusive ones (a deliberate deviation from upstream, where an empty inclusive ROI keeps nothing).
- Mask history keeps a protected blank baseline: trimming drops the oldest undo state after it, so Reset always restores the blank mask.
- A killed averaging job keeps its `killed` status. An averaging job with
  zero accepted inputs ends in a terminal `finished`
  state with zero accepted inputs recorded and no output file; no GUI path may
  try to open an output for it.

## Decisions left to the builder

- Which layers besides draw and parameter use replace semantics, as long as
  existing undo/redo/reset tests pass.
- Exact ROI adapter structure and where vertex conversion lives.
- The two stability key names and the terminal state name for an empty
  averaging job, provided the behaviour above holds.
- scikit-image lower bound (use what `uv lock` resolves on Python 3.12-3.14).

## Open items

- The APS comparisons (V31) stay unverified until raw frames, an unnormalised
  G2 cube and a registered Q-map are available.
- M31/M32/M35 and V20 are deferred, not rejected.
- A UI entry for an explicit fixed fit value (instead of "midpoint of the
  bounds") is deferred; revisit if users need per-parameter fixed values.
